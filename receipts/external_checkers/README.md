# Independent Third-Party Kernel Verification Receipts (`nanoda_bin` & `con-ron`)

All five flagship theorems of `Track2Grover.FindAnyLowerBound` and all four public challenge theorems of `Track2Grover.TighterFindAny` were exported to NDJSON format `3.1.0` via `leanexport.exe` (`lean4export` 3.1.0, bundled with Lean `4.35.0` toolchain `eb6cafb7290e8bd5f2937522d8d804f58f02bafc`) and checked by two independent Rust Lean 4 kernels bundled with the same toolchain:

1. **`nanoda_bin` 0.4.19** (`https://github.com/ammkrn/nanoda_lib`, SHA-256 `de57d9dd7f647eb57398bc3dab4dcaa1d64f961f3f49964d5455fbddc73b35a8`): strictly enforced `permitted_axioms = ["propext", "Classical.choice", "Quot.sound"]` with `unpermitted_axiom_hard_error = true`. Checked `49,235` (`FindAnyLowerBound`) and `46,246` (`TighterFindAny`) environment constants with exit code `0`.
2. **`con-ron --verified`** (formally verified Rust arena Lean 4 checker bundled in the Lean `4.35.0` toolchain, SHA-256 `4e351dd1d556da22efb44c17be30e3ff3900780730ce642ee007d1416d332d40`): accepted `47,256` (`FindAnyLowerBound`) and `44,302` (`TighterFindAny`) declaration records with exit code `0`.

**Why the two declaration counts differ (`49,235` vs `47,256`, and `46,246` vs `44,302`):** As documented in `con-ron --help` (*"THE VERDICT LINE'S COUNT"*), `con-ron` counts accepted `lean4export` declaration *records* (one record per `inductive` block, `def`, `theorem`, `opaque`, `axiom`, or `quot`), whereas `nanoda_bin` counts individual expanded environment *constants* (counting inductive type formers, constructors, and recursors separately). Both checkers processed the exact same exported NDJSON streams (`SHA-256 377bfd71...` and `b68f75f0...`). The exact wrapper script used on the workstation is archived here as `run_external_checkers.py`.
