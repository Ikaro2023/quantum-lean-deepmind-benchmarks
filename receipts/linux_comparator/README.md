# Independent 64-bit Linux `lake comparator` Verification Receipts

This directory archives a **curated publication subset** of the full raw Linux verification run directories (`run1_fast/` and `run2_findall/`, executed on a separate 62 GiB RAM 64-bit Ubuntu 26.04.1 LTS host with Lean 4.35.0 `eb6cafb7`, Lake 5.0.0, and `bubblewrap` 0.11.1 without `--inadvisably-no-sandbox`).

- **Preserved original manifests:** The `RESULT_SHA256SUMS.txt` files inside `run1_fast/results/`, `run2_findall/results_findall/`, and `run2_findall/fix16/results_fix16/` are preserved verbatim from the Linux verifier; every file staged in this subset matches its recorded SHA-256 digest, while large non-essential auxiliary files from the original run directories (full console traces `run_full.log`, `lake exe cache get` logs, raw `mem_samples.tsv` / `env_samples.tsv`, and runner helper scripts) are omitted to keep the release compact.
- **Challenge configurations:** `comparator_configs/` contains the three exact JSON configs used for `TighterFindAny`, `Track2Weak.FindAllWeak`, and `Track2Grover.FindAll` (each verified key-for-key identical to the upstream `QuantumComputationSpecs/ChallengeJsons/Algorithms/*.json` file except `solution_module`); `ArcsinK25ConstCost` used the upstream `QuantumComputationSpecs/ChallengeJsons/Primitives/ArcsinK25ConstCost.json` file verbatim from `discoveries` (`a88de8ff`).
- **Equivalence of the `fix16` run to `v1.0.1`:** The Linux `fix16` verification applied the one-keyword diff `FindAllWeak.fix.diff` (`noncomputable def weakChosenBatch` -> `noncomputable abbrev weakChosenBatch`) directly on top of the `v1.0.0` Lean sources (`SHA256SUMS.txt` 381/381 verified), producing `Track2Weak/FindAllWeak.lean` with SHA-256 `8ba169948040f7c16f8ae9d7becf74c3275676321d0fcf31eac1eb5c470bdd9a`. Because `v1.0.1` modifies no other `.lean` file among the 279 staged Lean files, the Lean source tree verified in `fix16` is byte-for-byte identical to the Lean source tree packaged in `v1.0.1`.
- **Memory units:** Reported cgroup peaks (`13.14 GiB` = `14.11 GB` = `14,110,093,312` bytes for sign-only step 19; `6.57 GiB` = `7.06 GB` = `7,058,329,600` bytes for fixed weak-filter step `fix16`) are binary gibibytes (`1 GiB = 2^30` bytes) of whole-job `memory.peak`.
